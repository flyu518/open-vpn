## 本轮发现并修复

1. 空目录并行 MSBuild 暴露 Qt QML 元数据依赖竞态：注册目标先读取到空的 moc JSON。
   Windows Visual Studio 构建增加真实目标依赖和生成项目检查。修复后第三个全新 Qt 构建目录首次完整构建成功。
2. 原安装包缺少明确的 VC++ 运行库前置依赖。改为打包时要求完整、版本足够且签名有效的微软 x64 离线包，安装器安装前检查系统版本，不降低已有新版运行库。
3. 本机 Package Cache 中的已签名约 600 KiB 文件仅是启动器，不能当作完整离线运行库。
   校验器拒绝小包，并使用微软官网下载的完整包重新生成最终安装器。
4. 实际运行库更新返回 `3010`，暴露前置依赖执行过晚、重启状态不能及时传递的问题。
   改为 `ssInstall` 提取并运行前置依赖，在 Inno 评估 `NeedRestart` 前设置状态；增加回归断言。

本轮没有改变 Mac 的交互、共享连接状态机或路由策略语义。以上修复均提交后再生成最终候选。

## 实际安装结果

执行的对象就是上表最终 EXE，而非构建目录程序。使用 Inno 原生 `/SILENT /NORESTART /SP- /RESTARTEXITCODE=3010 /LOG=...` 完成覆盖升级；最终调用退出码 0，日志记录安装成功，服务 `openvpn` 为 Running，登记版本为 1.0.0。

本轮升级保留两条真实配置、原顺序和此前三个托管文件的内容哈希。连接次数和最近连接时间会正常更新，不能要求索引文件整体哈希不变。临时配置与真实配置分开，导入的测试项已移除，原始测试文件保留在忽略目录；没有删除真实配置或凭据。

普通用户实际启动安装目录应用；服务可用，未观察到之前的 named pipe Access denied，也未出现应用伴随命令行窗口。

### 重启状态不能省略

本机先前安装本轮完整运行库时，微软安装程序实际返回 `3010`（需要重启），已更新系统文件至 14.51.36247.0。
修复生命周期后的最终安装器再次升级时检测到版本已满足，跳过前置依赖，返回 0。
**这不消除先前的重启请求，本轮没有重启 Windows。**

因此，最终实现的 `3010` 上报路径有回归断言，但尚未在修复后的安装器上以“旧运行库 → 需要重启”的干净状态重新触发。
正式放行前仍应完成一次有前置依赖更新的安装、重启、服务恢复和普通用户启动验证；不得通过降级/删除当前系统运行库来制造测试环境。

## 最终安装版真实双连接

通过本项目安装版 UI 使用原有两条真实配置和系统安全存储凭据，没有使用官方客户端 UI，也没有读取或记录密码：

1. A 建立连接；B 随后建立连接，两张独立 Wintun 接口为 61、63；UI 计时和流量更新。
2. B 的重叠路由按兼容模式跳过，A 地址、路由和 DNS 的规范化快照哈希不变。
3. 只断开 B，A 保持在线，地址/路由/DNS 哈希不变。
4. 重连 B，等待 UI 确认已建立连接后检查两条隧道；A 快照仍不变。
5. 只断开 A，B 保持在线，其地址/路由/DNS 快照哈希不变。
6. 断开最后一条：本项目虚拟网卡、接口路由、本项目 NRPT 分流 DNS 和带所有权标记的 IPv6 防泄漏路由均清理为 0。
7. UI 管理测试后重新连接 A/B，恢复本轮开始时的双连接状态。

流量计数和真实握手不等于已经访问所有业务服务器。没有指定业务目标，本轮不宣称业务端到端可达性通过。

## 未测项和正式发布关卡

- 当前工具拒绝操作提权后的安装向导窗口。本轮实际 EXE 安装使用原生静默参数，**没有逐页代点最终安装向导**；0.0.14 的旧向导实测不能重标成本包全部页面通过。
- 托盘菜单无法作为可定位窗口操作，本轮没有对 1.0.0 托盘每项、关于页及更新下载安装做完整点击验证；历史版本用户人工反馈单独保留。
- 未重启；没有执行重启后自动启动、服务恢复或运行库前置依赖更新后的干净系统回归。
- 未执行卸载、不同安装目录、各版本 Windows 和其他硬件上的全覆盖验证。
- Mac 两种目标架构仍须测试同一源码候选，不能沿用 0.0.3 历史记录。
- 自有安装器/程序签名、Mac 签名公证及跨平台资产汇总发布关卡尚未就绪；现有 Mac workflow 仍会直接发布，不能现在推正式 tag。

结论：可交接的 **Windows 1.0.0 内部测试候选**；上述已测结果成立，但不是“两端全部验收通过”或正式 Release。
